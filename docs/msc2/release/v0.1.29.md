# MSC 2 v0.1.29

This prerelease corrects automatic remote pairing, removes unnecessary health
polling during normal management, and fixes delayed shutdown reporting and
Intel Mac Bedrock VM worker exit.

## Remote desktop connections

- SSH pairing falls back to the installed `/usr/local/bin/msc` command when
  the remote shell cannot find `msc` on its search path.
- On macOS, pairing uses the installed agent service's configured secret
  storage when no explicit storage override is supplied. This fixes the
  desktop/SSH `MSC 2` versus legacy `MSC2` directory mismatch that could make a
  newly created pairing code appear already used.
- Pairing stays automatic; no manual code or shell-profile exports are needed
  for these corrected paths. Credentials remain inside the native boundary.

## Large modpack management

- Overview, Performance and Components request lightweight running status
  instead of full health diagnostics. There is no replacement health check
  on every start. Startup-failure diagnosis remains available.
- Retained full health calls count add-on files without opening every mod JAR.
  Blocking diagnostics run away from API worker threads, with one full check
  admitted at a time and bounded diagnostic subprocesses.
- Prevent overlapping Overview and Performance polling cycles. This addresses
  the repeated mod scans captured during All the Mods 10 management stalls.

## Shutdown and first-start completion

- The desktop continues checking lightweight status after the initial
  ten-second shutdown wait. It shows Stopping until the agent confirms exit,
  then returns to Start without a manual refresh.
- Routine status reconciliation also observes stops issued from another
  desktop or the Minecraft console. Old host responses cannot replace the
  selected host's state, and failed status reads are reported and retried.
- On Intel macOS, the Bedrock VM worker's run loop now returns after completed
  shutdown. The privileged helper still waits for actual worker exit before
  reporting termination, allowing agent Stopped status and initiation
  completion to advance. Non-root worker ownership remains intact.

## Installation and verification

Install the matching desktop update. On Intel macOS, use Repair agent from
that updated app to register its matching agent and Bedrock helper before
starting another Bedrock server. To verify remote pairing, remove any temporary
MSC PATH/storage exports previously added to the remote shell and connect
without a manual code or existing saved host credential.

The release workflow remains build-only and produces the complete nine
platform artifacts, SHA-256 checksums and signed update metadata. Release
builds and targeted compilation are not physical acceptance. New regression
cases were compiled but not executed; live acceptance of these fixes remains
open. The earlier unsigned-beta and platform support limits still apply.

Known issues remain under investigation: world swaps with folder names that
alias by case can be blocked on case-insensitive filesystems; Bedrock world
time can show Unavailable. This release does not change cheats settings or
claim a fix for either issue.
