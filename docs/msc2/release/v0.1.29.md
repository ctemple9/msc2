# MSC 2 v0.1.29

This prerelease supports large Bedrock saved-terrain map snapshots and includes
the Intel Mac Bedrock ownership correction from the unpublished v0.1.28 candidate.
It also preserves useful diagnostics when a converted world's activation fails.

## Large Bedrock maps

- Replace the 2 GiB proof snapshot limit with disk-space admission, a 2 GiB
  working reserve and a 1 TiB safety backstop.
- Use independent APFS copy-on-write file clones where available. Other
  filesystems use a fixed 1 MiB streaming buffer and periodic disk checks.
- Keep live save readiness and copying within one 30-second save-pause budget.
  Resume saving on failure. If a live copy cannot finish safely, stop the
  server and refresh terrain instead of extending the save hold.
- Give stopped-world copies a separate 30-minute deadline. Cancel on agent
  shutdown, server startup/run change or active-server change. Retain snapshot
  cleanup when the renderer releases it.
- The exporter still has its ten-minute deadline. Large-world physical rendering
  acceptance remains open; increasing snapshot capacity is not evidence that
  every world's catalog has completed rendering.

## Intel macOS packaging

The v0.1.28 Intel build rejected the rebuilt appliance because the desktop
stager retained its old pinned checksum. This candidate updates that declaration
and provides a local preparation option that runs the same checksum validation
without triggering a release workflow. All four checksum declarations agree
with the tracked appliance. No workflow jobs or test gates were added; the
v0.1.28 tag remains unchanged.

## Bedrock ownership

- The privileged helper keeps the TCP/UDP relays and supervises a fixed VM
  worker running as the installing account. Shared-folder writes therefore
  use the user's host identity instead of the root helper's identity.
- The worker refuses root or mismatched credentials. The guest also refuses
  missing, invalid or root identity instead of launching Bedrock as root.
- Stop the VM and reap its worker before acknowledging session termination.
  Keep the existing authenticated local socket and canonical server-path rules.
- Check existing macOS Bedrock world ownership before conversion or installing
  packs into an active world. Identify a misowned path before doing expensive
  world processing.

## Recovering existing worlds

The release prevents new root-owned writes; it does not silently change ownership
of old data. With Minecraft servers and the agent stopped, repair a verified
affected server directory once using your installing account and primary group:

```sh
sudo chown -R -P USER:GROUP "/absolute/path/to/affected/bedrock/server"
```

Start the agent afterward so it can finish any pending activation. Preserve
transaction folders. If conversion already saved a world slot, recover or
activate that slot instead of running conversion again.

Activation errors now retain the underlying cause and saved converted ZIP path,
and explain that the conversion does not need to be repeated.

## Installing

Stop Minecraft servers before updating. From v0.1.27, Settings uses the corrected
updater. From macOS v0.1.25 or v0.1.26, install the matching disk image manually
and repair the agent once; those versions contain the old rollback helper.

Nine packages remain available: Intel/Apple Silicon macOS desktop and headless,
x86_64 Windows desktop and headless, and Linux x86_64 DEB/RPM/headless. Apple
Silicon packages omit the local Bedrock VM. Checksums and signed update metadata
remain included. Desktop packages are unsigned and macOS is not notarized.

## Verification and limits

The specifically authorized snapshot regression command passed both focused
cases: crossing the old cumulative byte limit with an independent snapshot,
and stopping on cancellation, expired deadline or injected disk shortage. The
small controlled fixtures avoid sleeps, multi-gigabyte allocations and actual
disk-space assumptions. Rust Clippy and focused test-target compilation pass. The Swift
helper builds in Release and its XCTest target compiles in Debug. Guest shell
syntax, Python acceptance-script compilation and embedded appliance/source
consistency checks pass. Existing unrelated warnings remain.

The new opt-in `tools/phase16/check-bedrock-world-ownership.py` boots a disposable
small Bedrock world twice through the installed helper, verifies relay readiness
and actual host ownership, and checks deletion. This physical check has not yet
been run. Host ownership, RakNet/NetherNet connectivity and activation recovery
remain for owner acceptance on Intel hardware. Publication remains build-only.

The owner confirmed that the five-hour Tectonic conversion passed Chunker and
produced a saved slot that could be activated after the generic activation
failure. The 94.42% pause was observed in Bedrock database compaction and later
progressed. This release does not claim faster Chunker compaction or improved
pack-install progress. The reported Prizma Visuals installation outcome remains
unconfirmed.
