# MSC 2 v0.1.30

This prerelease fixes XboxBroadcast being cancelled during Bedrock status
polling and prevents its helper download from blocking broadcast control and
output handling. It includes the existing v0.1.29 connection and shutdown fixes.

## XboxBroadcast and Bedrock

- Preserve Bedrock console, metrics and readiness events arriving while the
  agent waits for a command or startup reply. The actual acknowledgement is
  consumed by its request instead of later being rejected as an event.
- A recoverable event-reading error no longer stops broadcast while the
  Bedrock runtime still reports a live server. Cleanup remains in place for
  lost runtimes and confirmed termination. Event errors now reach both the
  server console and agent log instead of silently cancelling helpers.
- Broadcast startup returns its managed operation before downloading the
  helper. Provider downloads run outside the broadcast state lock and away
  from async API workers. Status, output and Stop can continue during that work.
- Stopped, cancelled or replaced preparations cannot launch a late helper or
  fail a newer operation. Artifact acquisition is serialized separately so
  overlapping requests cannot overwrite shared staging files.
- Existing transport selection is retained. This release does not switch
  RakNet servers to NetherNet or claim to resolve NetherNet connectivity.

Cameron confirmed the temporary native Intel build resolves the reported
broadcast-start failure on the affected Mac with RakNet retained. That is live
acceptance of the reported correction, not proof of every fault case or every
platform's new release artifact. Focused regressions were compiled, not run.

## Installation

Install the matching desktop update. On Intel macOS, stop Minecraft, replace
the app and use **Repair agent** from the updated app before the next server
start, so the service uses the corrected bundled agent. This normal release
supersedes the temporary local XboxBroadcast app ZIP. Settings and worlds are
retained. Headless hosts update the matching agent through the existing local
installation/update flow.

## Release and remaining work

The existing build-only workflow produces all nine desktop/headless artifacts,
SHA-256 checksums and signed update metadata. Release dependency caching and
shared compilation output now avoid the previously duplicated agent build in
payload staging. Cache availability and total build-time improvement remain
unmeasured; no new CI or test gates were added.

The rolling plan has been reconciled and now contains the planned native
upload/import improvements. **Those performance changes are not implemented
in this release.** The current upload path and its limits remain unchanged.

Known world-time and case-alias world-swap observations remain deferred. The
existing unsigned-beta and platform support limits still apply. Successful
publication does not close the broader physical release acceptance gate.
