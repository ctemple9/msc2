# MSC 2 v0.1.32

This prerelease makes the saved-terrain map faster to revisit and brings Bedrock
onto the Java map's renderer and controls. The first preparation of a large
world can still take time; the new preparation and tile caches are intended to
make later visits and unchanged refreshes cheaper.

## Saved-terrain maps

- Java preparation uses bounded parallel region conversion, retains compatible
  converted regions and detailed tiles across app and agent restarts, and gives
  camera-visible tiles priority while travelling. An explicit **Pre-render map**
  operation can fill the detailed cache in advance; it reports progress and
  storage use and can be stopped and resumed.
- Java **Refresh terrain** compares saved chunk content and rebuilds affected
  tiles while keeping the current map and camera visible.
- Bedrock now converts its saved LevelDB terrain into private region input and
  uses the same Vantage viewer, tile streaming, persistent detailed cache,
  optional pre-render operation, and camera-following detail path as Java. Its
  first open shows saved-region preparation progress before the detailed view.
  Converted regions can be reused on later opens. Bedrock refresh retains
  unchanged prepared regions and uses the shared tile revision mechanism.
- Bedrock block translation now renders representative terracotta, paths,
  sugar cane, logs, doors and glass panes with the expected models and states.
  Biome names for matching Bedrock 1.26.60 saves no longer all appear as Plains;
  unknown IDs use an explicit neutral fallback. The biome palette now grows as
  detailed terrain streams, preventing the black patches seen with Biomes on.
- Depth changes no longer pull the camera toward the terrain surface between
  slider or Option-arrow increments in the shared Java/Bedrock viewer.

Cameron confirmed the latest Bedtonic map and biome-colour correction work in
his local optimized build. The side-by-side Java/Bedrock timing worksheet,
pre-render Stop/Resume, changed-terrain refresh, other Bedrock save versions,
other platforms, and exact published artifacts remain separate physical checks.
This release does not claim measured Java/Bedrock speed parity.

## Installation and release status

Install the matching desktop update. On Intel macOS, quit MSC 2, replace the
app, and use **Repair agent** so the service runs the matching bundled agent.
Existing servers and worlds are retained. Headless hosts update through the
existing local agent installation flow.

The build-only release workflow produces the nine desktop and headless
artifacts, SHA-256 checksums, and signed update metadata. The installers are
not publisher-signed or notarized. Successful publication does not close the
separate physical release acceptance gate.
